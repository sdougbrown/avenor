# Workflow completion command — `avenor stable` + `avenor workflow`

## What it proves

A node with `completion.kind: "command"` is completed by the supervisor itself
after its worker exits successfully: the supervisor runs the declared check argv
in the attempt's working directory, with no shell and an empty environment,
requires exit 0, and resolves declared `{"command": "stdout", "pointer": ...}`
outputs from it. A non-zero check leaves the contract unmet
(`contract_unmet`), so the node's retry policy applies.

Either way the run leaves durable evidence — the capped stdout and stderr, plus
a summary naming the argv, termination, exit code, duration, and stream digests
— that `avenor workflow inspect` returns on the attempt's activation, and each
entry names the exact attempt it belongs to. The check's output is owner-only
evidence and never quoted into the supervisor's log, so a failed check is read
exactly like a passing one.

The check below passes only when it observes the external state the fixture
prepared *and* sees no ambient environment, so a completed workflow is direct
proof of both properties.

## Prerequisites (cross-ref `../SKILL.md` and `stable-control.md`)

- Build the binary: `mise run go-build` (→ `./avenor`).
- Doctor: `command -v pi` — the backend must exist with a working default
  model. Export `MODEL` to an installed Pi model before running the recipe
  (configured local/home models are valid).
- Fresh short scratch `SCRATCH=$(mktemp -d /tmp/avenor-verify.XXXXXX)`, with
  separate workflow/adapter roots isolated from the defaults:
  `--workflow-root "$SCRATCH/workflows"` and
  `--workflow-adapter-dir "$SCRATCH/adapters"` (create `adapters` as `0700`).
- Operator-supplied harmless check: reads `state.yaml` in the attempt's working
  directory and prints one JSON object. This fixture does not isolate the state
  from the worker.

## Fixture (runnable; the JSON is generated by the embedded python)

```bash
set -eu; cd "$(git rev-parse --show-toplevel)"   # repo root, where ./avenor lives
SCRATCH=$(mktemp -d /tmp/avenor-verify.XXXXXX); WORK="$SCRATCH/work with spaces \$literal"
mkdir -p "$WORK"; mkdir -m 0700 "$SCRATCH/adapters"; SOCK="$SCRATCH/s.sock"
: "${MODEL:?Set MODEL to an installed Pi model}"
exec 3>"$SCRATCH/commands.log"; export BASH_XTRACEFD=3; set -x
# External state the check observes. Left "not-ready" here; each drive sets the
# state its own check must see.
printf 'not-ready\n' > "$WORK/state.yaml"
# Shell builtins only: the check's environment is empty, so there is no PATH to
# find an interpreter with. It rejects any ambient environment, which makes a
# completed workflow proof that the empty environment reached it.
CHECK="$SCRATCH/check-state"
{
  printf '#!/bin/sh\n'
  printf 'set -eu\n'
  printf 'exported=$(export -p)\n'
  printf 'case "$exported" in *"PATH="*) printf "ambient PATH leaked\\n" >&2; exit 5;; esac\n'
  printf 'case "$exported" in *"HOME="*) printf "ambient HOME leaked\\n" >&2; exit 5;; esac\n'
  printf 'read -r state < state.yaml\n'
  printf '[ "$state" = "ready" ] || { printf "state is %%s\\n" "$state" >&2; exit 3; }\n'
  printf 'printf '"'"'{"state":"%%s","dir":"%%s"}\\n'"'"' "$state" "$PWD"\n'
} > "$CHECK"
chmod 0700 "$CHECK"
python3 - "$SCRATCH" "$WORK" "$CHECK" "$MODEL" <<'PY'
import json, sys
s, work, check, model = sys.argv[1:5]
open(s + "/roster.json", "w").write(json.dumps({"worker": {"backend": "pi", "agent": "mule", "model": model, "thinking": "low"}}))
t = {"schema_version": 1, "template_id": "verify-command-completion", "template_version": "1",
     "entry_nodes": ["start"], "terminal_outcomes": ["done"],
     "params": [{"id": "run_dir", "type": "string", "required": True}],
     "working_directory": {"from_instance_param": "run_dir"},
     "default_lease_policy": {"ttl_seconds": 120, "heartbeat_interval_seconds": 10},
     "nodes": [{"id": "start", "action": {"type": "run", "prompt": "Reply with the single word OK and nothing else."},
         "assignment": {"role": "worker", "roster_file": s + "/roster.json", "roster_entry": "worker"},
         "dispatch": {"mode": "auto", "controller_id": "verify-command"},
         "completion": {"kind": "command", "command": {"argv": [
             {"type": "literal", "value": check},
             {"type": "literal", "value": "--read-only"},
             {"type": "instance_param", "from_instance_param": "run_dir"}],
             "timeout_seconds": 30}},
         "outputs": [{"id": "state", "name": "State", "type": "string", "required": True,
             "source": {"command": "stdout", "pointer": "/state"}}],
         "retry_policy": {"max_attempts": 2, "exhaustion": "block"},
         "outcomes": [{"name": "done", "terminal": True}]}]}
open(s + "/template.json", "w").write(json.dumps(t, indent=2) + "\n")
open(s + "/controller.json", "w").write(json.dumps({"controller_id": "verify-command", "max_inflight": 1}) + "\n")
open(s + "/instance.json", "w").write(json.dumps({"params": {"run_dir": work}}) + "\n")
PY
```

## Drive (full real commands; only the polling loop is elided control flow)

```bash
printf 'ready\n' > "$WORK/state.yaml"   # the external state this check must observe
./avenor stable --control-socket "$SOCK" \
  --workflow-root "$SCRATCH/workflows" --workflow-adapter-dir "$SCRATCH/adapters" \
  --max-runtimes 2 --idle-timeout 8m --shutdown-timeout 10s &> "$SCRATCH/stable.log" &
STABLE_PID=$!   # record this — cleanup kills THIS pid only (see stable-control.md)
for _i in $(seq 1 50); do   # ~10 s deadline
  kill -0 "$STABLE_PID" 2>/dev/null || { echo "FAIL: supervisor exited"; exit 1; }
  ./avenor control --socket "$SOCK" list >/dev/null 2>&1 && break
  sleep 0.2
done
./avenor control --socket "$SOCK" list >/dev/null 2>&1 || { echo "FAIL: socket not ready"; exit 1; }

./avenor workflow create --socket "$SOCK" --request-file "$SCRATCH/template.json"
./avenor workflow controller create --socket "$SOCK" --request-file "$SCRATCH/controller.json"
WF=$(./avenor workflow instantiate --socket "$SOCK" --template-id verify-command-completion --template-version 1 --request-file "$SCRATCH/instance.json" | python3 -c 'import json,sys;print(json.load(sys.stdin)["workflow_id"])')

./avenor workflow ready --socket "$SOCK" verify-command          # advisory check
./avenor workflow controller enable --socket "$SOCK" verify-command
for _i in $(seq 1 120); do   # ~60 s deadline
  kill -0 "$STABLE_PID" 2>/dev/null || { echo "FAIL: supervisor exited"; exit 1; }
  S=$(./avenor workflow status --socket "$SOCK" "$WF" | python3 -c 'import json,sys;print(json.load(sys.stdin)["status"])')
  case "$S" in completed) break;; blocked|failed|canceled) echo "FAIL: $S"; exit 1;; esac
  sleep 0.5
done
S=$(./avenor workflow status --socket "$SOCK" "$WF" | python3 -c 'import json,sys;print(json.load(sys.stdin)["status"])')
[ "$S" = "completed" ] || { echo "FAIL: timed out, status=$S"; exit 1; }
```

### Failure variant

Same fixture and the same running supervisor, a separate workflow. The state the
check reads must be `not-ready` for this variant, so set it here explicitly —
the success drive flipped it to `ready`, and the check is what decides which
state it sees. The check exits 3, both declared attempts are recorded `failed` /
`contract_unmet` **with** their check's evidence, no output is recorded, and the
activation ends `blocked`. Restore `ready` afterwards so the recorded fixture
state matches the success drive.

```bash
printf 'not-ready\n' > "$WORK/state.yaml"   # this variant's external state
WF_FAIL=$(./avenor workflow instantiate --socket "$SOCK" --template-id verify-command-completion --template-version 1 --request-file "$SCRATCH/instance.json" | python3 -c 'import json,sys;print(json.load(sys.stdin)["workflow_id"])')
for _i in $(seq 1 120); do
  A=$(./avenor workflow inspect --socket "$SOCK" "$WF_FAIL" | python3 -c 'import json,sys;d=json.load(sys.stdin);print(next(a["status"] for a in d["activations"] if a["node_id"]=="start"))')
  [ "$A" = "blocked" ] && break
  sleep 0.5
done
./avenor workflow inspect --socket "$SOCK" "$WF_FAIL" > "$SCRATCH/inspect-unmet.json"
python3 - "$SCRATCH/inspect-unmet.json" <<'PY'
import json, sys
d = json.load(open(sys.argv[1]))
a = d["attempts"]; a = list(a.values()) if isinstance(a, dict) else a
bad = [x for x in a if x["status"] == "failed" and x.get("marker_label") == "contract_unmet"]
assert len(bad) == 2, bad
assert not d.get("outputs"), d.get("outputs")
attempt_ids = {x["attempt_id"] for x in bad}
ev = d.get("evidence") or []
stdout = [e for e in ev if e["stored_path"].endswith("completion-command.stdout")]
stderr = [e for e in ev if e["stored_path"].endswith("completion-command.stderr")]
assert len(stdout) == 2 and len(stderr) == 2, ev
for e in stdout:
    summary = e["result"]
    assert summary["exit_code"] == 3, summary
    assert summary["termination"] == "exited", summary
    assert summary["stdout_sha256"] == e["sha256"], (summary, e)
    assert "state is not-ready" in summary["diagnostic"], summary
    # Evidence names the exact attempt, and each retry keeps its own.
    assert e["attempt_id"] in attempt_ids, e
assert {e["attempt_id"] for e in stdout} == attempt_ids, stdout
print("FAILURE VARIANT OK")
PY
printf 'ready\n' > "$WORK/state.yaml"   # restore the success drive's external state
```

## Evidence (capture before cleanup; copy out of the scratch dir first)

```bash
EV=/tmp/avenor-verify-evidence/$(date +%Y%m%d-%H%M%S); mkdir -p "$EV"
./avenor workflow status --socket "$SOCK" "$WF" > "$EV/workflow-status.json"
./avenor workflow inspect --socket "$SOCK" "$WF" > "$EV/workflow-inspect.json"
./avenor workflow events --socket "$SOCK" "$WF" --after-seq 0 --limit 100 > "$EV/workflow-events.json"
./avenor workflow controller status --socket "$SOCK" verify-command > "$EV/controller-status.json"
RT=$(python3 -c 'import json;a=json.load(open("'"$EV"'/workflow-inspect.json"))["attempts"];a=list(a.values()) if isinstance(a,dict) else a;print(a[0]["identity"]["runtime_id"])')
./avenor control --socket "$SOCK" status "$RT" > "$EV/runtime-status.json"
# The runtime's own sentinel and event log are part of the proof (see SKILL.md).
cp "$(python3 -c 'import json;print(json.load(open("'"$EV"'/runtime-status.json"))["sentinel_file"])')" "$EV/done.env"
cp "$(python3 -c 'import json;print(json.load(open("'"$EV"'/runtime-status.json"))["on_event"])')" "$EV/events.ndjson"
# The failure variant's inspect payload, staged out of the scratch dir before
# cleanup removes it.
[ -f "$SCRATCH/inspect-unmet.json" ] && cp "$SCRATCH/inspect-unmet.json" "$EV/inspect-unmet.json"
# Copy every completion-command evidence file (the success run's, and both retry
# attempts' when the failure variant ran) and verify each one's bytes against
# the digest the inspect payload recorded.
python3 - "$EV" "$SCRATCH/workflows" <<'PY'
import hashlib, json, os, sys
ev, root = sys.argv[1:3]
copied = 0
for name in ("workflow-inspect.json", "inspect-unmet.json"):
    path = os.path.join(ev, name)
    if not os.path.exists(path):
        continue
    d = json.load(open(path))
    workflow_id = d["workflow_id"]
    written = set()
    for e in d.get("evidence", []):
        stored_path = e.get("stored_path", "")
        if "completion-command." not in stored_path:
            continue
        # One file per staged copy: the evidence id is unique, so a retry's
        # stdout and stderr never overwrite an earlier attempt's. Naming by
        # workflow and stream alone would collide on every retry.
        out = "%s-%s-%s" % (workflow_id, e["evidence_id"], os.path.basename(stored_path))
        assert out not in written, "two evidence entries map to %s" % out
        written.add(out)
        with open(os.path.join(root, "instances", workflow_id, stored_path), "rb") as handle:
            data = handle.read()
        # The bytes are read once, so the digest that is verified is the digest
        # of exactly the bytes written out below.
        digest = hashlib.sha256(data).hexdigest()
        assert digest == e["sha256"], (out, digest, e["sha256"])
        assert len(data) == e.get("size", len(data)), (out, len(data), e.get("size"))
        with open(os.path.join(ev, out), "wb") as handle:
            handle.write(data)
        with open(os.path.join(ev, out), "rb") as handle:
            assert handle.read() == data, "copied bytes differ from %s" % out
        with open(os.path.join(ev, out + ".evidence.json"), "w") as handle:
            json.dump(e, handle, indent=2)
        copied += 1
    on_disk = {f for f in os.listdir(ev)
               if f.startswith(workflow_id + "-ev_") and not f.endswith(".evidence.json")}
    assert written <= on_disk, (workflow_id, sorted(written - on_disk))
assert copied > 0, "no completion-command evidence was found"
print("copied, size-checked, hash-verified, and read back %d completion-command evidence files" % copied)
PY
cp "$WORK/state.yaml" "$EV/state.yaml"
cp "$SCRATCH"/{template,controller,instance,roster}.json "$EV/"   # full fixture files
cp "$SCRATCH/commands.log" "$EV/"   # stable command argv + full transcript
cp "$SCRATCH/stable.log" "$EV/"     # supervisor diagnostics, which never quote the check's output
./avenor control --socket "$SOCK" shutdown graceful
kill "$STABLE_PID" 2>/dev/null || true
wait "$STABLE_PID" 2>/dev/null || true
rm -rf "$SCRATCH"   # never delete "$EV"
```

## Observable end state (the proof)

- `workflow-status.json`: `"status": "completed"`, `"terminal_outcome": "done"`.
- `workflow-inspect.json`: **exactly one** attempt, `"status": "succeeded"`,
  one output `state` = `"ready"`, and one evidence entry whose `stored_path`
  ends `completion-command.stdout`, with a non-empty `sha256` and a `size`,
  whose `attempt_id` is that attempt's id and whose `result` names the check's
  `argv`, `"termination": "exited"`, `"exit_code": 0`, a `duration_ms`, and
  `stdout_sha256` equal to the entry's `sha256`.
- The copied `<workflow-id>-<evidence-id>-completion-command.stdout` holds the
  check's exact bytes,
  `{"state":"ready","dir":"<the attempt's working directory>"}` — proving the
  check ran in the attempt's directory, not the supervisor's. Each staged copy
  keeps its own evidence id in its filename, so a retry's stdout/stderr and its
  `.evidence.json` sit next to the earlier attempt's instead of replacing them,
  and the copy step verifies every file's size and SHA-256 and reads it back
  byte-for-byte.
- `done.env` and `events.ndjson`: the attempt runtime's own sentinel (`DONE`,
  `STOP_REASON=end_turn`) and full event stream, read from the paths the runtime
  status names.
- `stable.log`: the supervisor's diagnostics never quote the check's output; the
  check's report lives only in the staged evidence (the failure variant's
  `stable.log` names the exit status, not the check's stderr).
- Because the check exits non-zero when `PATH` or `HOME` is set, a completed
  workflow also shows those variables were not passed in its environment. This
  does not prove isolation from the supervisor's credentials or other files.
- Failure variant: two `failed` / `contract_unmet` attempts, the activation
  `blocked`, no output recorded, and — because a failed check is evidence too —
  one `completion-command.stdout` and one `completion-command.stderr` entry per
  failed attempt, each naming its own `attempt_id` with its `sha256`, the stdout
  entry's `result` naming `"exit_code": 3`, `"termination": "exited"`, and the
  check's `"diagnostic": "state is not-ready"`. The staged stdout is empty (the
  check prints nothing) and the staged stderr holds the report.

## Gotchas

- The check is a real program the supervisor execs directly: no shell wrapper,
  no `PATH` lookup. `argv[0]` must be a literal absolute path, and every other
  element is one argv element — an instance param holding spaces or `$` arrives
  unchanged and is never expanded.
- An empty environment means the check cannot rely on `PATH`: the fixture check
  is shell builtins only, and a real template must call any interpreter by its
  absolute path.
- A check's argv and output can hold sensitive data. Evidence is owner-only
  (`0600` files in `0700` directories) for a workflow root this version creates,
  and the supervisor's log never quotes the captured streams; tightening an
  existing root is your call. The check runs as the supervisor's user, which is
  not isolation from the worker.
- `timeout_seconds` is required and must be 1–300; a hung check is killed by its
  process group at the deadline, and the attempt lands `contract_unmet`.
- Stdout is capped at 64 KiB and stderr at 16 KiB. A check that needs to report
  more should summarise; the staged stdout is what an operator reads later.
- A recovery can re-dispatch the node and re-run the check: keep it read-only
  and idempotent.
- Cleanup is `control shutdown graceful` + the recorded `STABLE_PID` only —
  never `pkill`; copy evidence out before `rm -rf` of the scratch dir.
