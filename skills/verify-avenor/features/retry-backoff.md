# Workflow retry backoff — `avenor stable` + `avenor workflow`

## What it proves

A node's `retry_policy.backoff_seconds` delays each re-armed attempt: after a
failed attempt with budget left, the activation stays `ready` but is not
dispatchable until its persisted not-before readiness time (one backoff
interval after the termination) passes — so a retry budget cannot be spent
inside one transient outage. The readiness time survives a supervisor
restart (it is stamped onto the re-arm event and replayed), and exhaustion
still applies once the budget is gone.

## Prerequisites (cross-ref `../SKILL.md` and `stable-control.md`)

- Build the binary: `mise run go-build` (→ `./avenor`).
- Doctor: `command -v pi` — the backend must exist with a working default
  model. Export `MODEL` to an installed Pi model before running the recipe.
- Fresh short scratch `SCRATCH=$(mktemp -d /tmp/avenor-verify.XXXXXX)`, with
  `--workflow-root "$SCRATCH/workflows"` and
  `--workflow-adapter-dir "$SCRATCH/adapters"` (create `adapters` as `0700`).
- The attempt must fail: the node declares a `files` completion contract on
  an artifact the agent never writes, so the run ends `end_turn` and the
  contract comes back unmet — a `failed` attempt that consumes retry budget.

## Fixture (runnable; the JSON is generated by the embedded python)

```bash
set -eu; cd "$(git rev-parse --show-toplevel)"   # repo root, where ./avenor lives
SCRATCH=$(mktemp -d /tmp/avenor-verify.XXXXXX); mkdir -m 0700 "$SCRATCH/adapters"; SOCK="$SCRATCH/s.sock"
: "${MODEL:?Set MODEL to an installed Pi model}"
python3 - "$SCRATCH" "$MODEL" <<'PY'
import json, sys
s, model = sys.argv[1:3]
open(s + "/roster.json", "w").write(json.dumps({"worker": {"backend": "pi", "agent": "mule", "model": model, "thinking": "low"}}))
t = {"schema_version": 1, "template_id": "verify-retry-backoff", "template_version": "1",
     "entry_nodes": ["start"], "terminal_outcomes": ["done"],
     "nodes": [{"id": "start", "action": {"type": "run", "prompt": "Reply with the single word OK and nothing else."},
         "assignment": {"role": "worker", "roster_file": s + "/roster.json", "roster_entry": "worker"},
         "dispatch": {"mode": "auto", "controller_id": "verify-backoff"},
         "completion": {"kind": "files", "artifacts": [{"path": "backoff-marker.txt", "non_empty": True}]},
         "retry_policy": {"max_attempts": 2, "exhaustion": "block", "backoff_seconds": 15},
         "outcomes": [{"name": "done", "terminal": True}]}]}
open(s + "/template.json", "w").write(json.dumps(t, indent=2) + "\n")
open(s + "/controller.json", "w").write(json.dumps({"controller_id": "verify-backoff", "max_inflight": 1}) + "\n")
open(s + "/instance.json", "w").write(json.dumps({}) + "\n")
# Negative backoff must be rejected by template validation.
neg = json.loads(json.dumps(t)); neg["template_id"] = "verify-backoff-negative"
neg["nodes"][0]["retry_policy"]["backoff_seconds"] = -1
open(s + "/template-negative.json", "w").write(json.dumps(neg, indent=2) + "\n")
PY
```

## Drive (full real commands; only the polling loops are elided control flow)

```bash
./avenor stable --control-socket "$SOCK" \
  --workflow-root "$SCRATCH/workflows" --workflow-adapter-dir "$SCRATCH/adapters" \
  --max-runtimes 2 --idle-timeout 8m --shutdown-timeout 10s &> "$SCRATCH/stable.log" &
STABLE_PID=$!   # record this — cleanup kills THIS pid only (see stable-control.md)
for _i in $(seq 1 50); do
  kill -0 "$STABLE_PID" 2>/dev/null || { echo "FAIL: supervisor exited"; exit 1; }
  ./avenor control --socket "$SOCK" list >/dev/null 2>&1 && break
  sleep 0.2
done

# Validation: a negative backoff is rejected at template create time.
if ./avenor workflow create --socket "$SOCK" --request-file "$SCRATCH/template-negative.json" 2>err.txt; then
  echo "FAIL: negative backoff accepted"; exit 1
fi
grep -q "backoff_seconds must not be negative" err.txt || { echo "FAIL: wrong error"; exit 1; }

./avenor workflow create --socket "$SOCK" --request-file "$SCRATCH/template.json" >/dev/null
./avenor workflow controller create --socket "$SOCK" --request-file "$SCRATCH/controller.json" >/dev/null
WF=$(./avenor workflow instantiate --socket "$SOCK" --template-id verify-retry-backoff --template-version 1 --request-file "$SCRATCH/instance.json" | python3 -c 'import json,sys;print(json.load(sys.stdin)["workflow_id"])')
./avenor workflow controller enable --socket "$SOCK" verify-backoff

# Stage A: poll inspect until attempt 1 has terminated and the activation
# re-armed (`status == "ready"` with exactly one attempt), then confirm the
# activation is still held (still one attempt) a few seconds later — the
# controller does not dispatch during the backoff window.
#   status:    ./avenor workflow inspect --socket "$SOCK" "$WF"
#   attempts:  length of "attempts"; activation status: activations[0].status
# Stage B: poll status until it reports "blocked" (budget exhausted with
# exhaustion "block"); capture evidence below on the way.

EV=/tmp/avenor-verify-evidence/$(date +%Y%m%d-%H%M%S); mkdir -p "$EV"
./avenor workflow status --socket "$SOCK" "$WF" > "$EV/workflow-status.json"
./avenor workflow inspect --socket "$SOCK" "$WF" > "$EV/workflow-inspect.json"
./avenor workflow events --socket "$SOCK" "$WF" --after-seq 0 --limit 200 > "$EV/workflow-events.json"
cp "$SCRATCH"/{template,controller,instance,roster}.json "$EV/"
cp "$SCRATCH/stable.log" "$EV/"

# The arithmetic proof: attempt 2 must not start before the not-before time.
python3 - "$EV/workflow-events.json" <<'PY'
import json, sys, datetime
events = json.load(open(sys.argv[1]))
events = events if isinstance(events, list) else events.get("events", [])
terms = [e for e in events if e.get("kind") == "workflow.event.attempt_terminated"]
starts = [e for e in events if e.get("kind") == "workflow.event.leased"]
def at(e): return datetime.datetime.fromisoformat(e["at"].replace("Z", "+00:00"))
gap = (at(starts[1]) - at(terms[0])).total_seconds()
assert gap >= 15, f"attempt 2 started {gap:.0f}s after attempt 1 terminated; backoff not honored"
print(f"PASS: gap {gap:.0f}s >= 15s backoff")
PY

./avenor control --socket "$SOCK" shutdown graceful
kill "$STABLE_PID" 2>/dev/null || true
wait "$STABLE_PID" 2>/dev/null || true
rm -rf "$SCRATCH"   # never delete "$EV"
```

## Observable end state (the proof)

- Negative template: create fails with
  `invalid workflow template: node "start" retry_policy: backoff_seconds must not be negative`.
- `workflow-status.json`: `"status": "blocked"` (exhaustion `block` after the
  second failed attempt).
- `workflow-inspect.json`: exactly **two** attempts, both `failed`; the
  activation shows `status: "ready"` between the attempts with a `ready_at`
  exactly one backoff interval after attempt 1's termination.
- `workflow-events.json`: the second `workflow.event.leased` is at or after
  `ready_at` — the gap from attempt 1's `attempt_terminated` to attempt 2's
  lease is ≥ `backoff_seconds` (measured 16s against a 15s backoff), and the
  re-armed activation was observed held (one attempt, no dispatch) during
  the window.

## Gotchas

- The contract-unmet attempt is the cheap failure: the one-word run ends
  normally, the missing artifact marks the attempt failed, and retry
  semantics apply. Do not use a nonexistent backend or wrapper — a start
  failure finalizes as `canceled`, which never retries.
- The activation's `ready_at` is a **not-before** time, not an age stamp:
  `workflow ready` (advisory candidate query) lists it even while held; the
  dispatch selection policy, not the candidate query, is what gates it.
- `backoff_seconds` is optional and defaults to zero (immediate re-arm);
  negative values are rejected by template validation, not clamped.
- Cleanup is `control shutdown graceful` + the recorded `STABLE_PID` only —
  never `pkill`; copy evidence out before `rm -rf` of the scratch dir.
